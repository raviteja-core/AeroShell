# AeroShell Deviations Register

This document tracks all intentional divergences from `docs/REFERENCE.md`, noting the reason, the affected files, and the alternative implementation.

| # | Reference Section | Specified Behavior | Divergence / Actual Implementation | Rationale |
|---|---|---|---|---|
| DEV-001 | §2 Baseline, §5.6 package.json | `electron: "44.4.5"` | Pinned exactly to `electron: "44.5.1"` | `44.5.1` is the newest stable patch in the Electron 44.x line (verified via `npm view electron@44 version`). Same version used in `compile:native`. |
| DEV-002 | §2 Baseline, §5.1 Native | `cmake-js: 7.x` | Pinned to `cmake-js: "8.0.0"` | `8.0.0` is the current stable major with full support for Node 24 LTS and modern CMake toolchains. |
| DEV-003 | §5.3 Main process | M0 imports protocol-handler, ipc, watchdog, crash-monitor | M0 `src/main/index.ts` is minimal (single-instance lock + blank `BrowserWindow` with hardened webPreferences). Subsequent modules are integrated in M1–M5. | As specified in the milestone execution plan to verify scaffolding and typecheck cleanly before downstream modules are implemented. |
| DEV-004 | §5.6 Scripts & Gates | M0 gate: `npm start` | Added automated smoke test `tests/e2e/smoke.test.ts` (Playwright launch, wait for `ready-to-show`, exit 0) for verifiable CI and CLI gating. | Prevents hanging headless/terminal sessions during automated gate verification. |
| DEV-005 | §7.1 Chromium Switches | Software GL flags | `AEROSHELL_TEST_SOFTWARE_GL=1` env var triggers `--use-gl=angle --use-angle=swiftshader` strictly for tests/CI; never present in prod code. | Allows test execution in headless Windows environments without physical GPUs. |
| DEV-006 | §5.1 Native module | `win_memory.cc` implicit ULONGLONG cast | Explicit `static_cast<double>(...)` applied to all `MEMORYSTATUSEX` ULONGLONG fields. | Prevents MSVC warning C4244 ('conversion from ULONGLONG to double, possible loss of data') which fails under `/W4 /WX`. |
| DEV-007 | §5.1 Native module | `/Qspectre` in compile options | Removed `/Qspectre` compiler flag | The MSVC v143 Spectre-mitigated libraries component is not installed in the build environment. Retaining the flag produces fatal error D8040 / link failure without the component. |
| DEV-008 | §5.1 Native module | System header warning isolation | Added `/external:anglebrackets /external:W0` and designated `node-addon-api` / Node headers as `SYSTEM`. | Guarantees `/W4 /WX` strictly audits AeroShell native codebase while preventing third-party header warnings from halting compilation. |
| DEV-009 | §9.1 CI, §9.2 Hardening | E2E test execution vs fused binary | E2E tests run against the development/unfused build; fuse validation is executed against the packaged distribution installer in M7. | Electron fuses (`RunAsNode=false`, `OnlyLoadAppFromAsar=true`) preclude test runner automation hooks on unpacked dev binaries. |
| DEV-010 | §5.1 Native module | Windows delay load hook linking | Injected `win_delay_load_hook.cc` and linked with `/DELAYLOAD:NODE.EXE` | On Windows, Electron executable names are `electron.exe` (or `<productName>.exe`) rather than `node.exe`. The delay-load hook intercepts `NODE.EXE` import resolutions at runtime and redirects them to the hosting module handle (`GetModuleHandle(NULL)`). |
| DEV-011 | §5.6 Packaging | `buildResources: build` in `electron-builder.yml` | Changed `buildResources` directory from `build` to `assets` | `cmake-js` builds native C++ binaries into `build/`. Using `build` for both native output and electron-builder packaging resources causes naming collisions and unintentional file inclusion in installer generation. |
| DEV-012 | §5.1 Native module, §7 GPU telemetry | `QueryVideoMemoryInfo` process scoping limitation | Renamed contract field to `mainProcessVramUsageMB` and plan PDH GPU performance counters for M5. In M4 HUD shows VRAM budget/total only. | `IDXGIAdapter3::QueryVideoMemoryInfo` strictly returns the VRAM footprint of the *calling process* (which is ~0 MB for Electron's browser/main process). It cannot be used alone for GPU-wide pressure detection. In M5, `getGpuCounters()` will add PDH query support (`\GPU Adapter Memory(*)\Dedicated Usage` and `\GPU Process Memory(pid_*)\Dedicated Usage`) with graceful degradation when PDH is unavailable. |
| DEV-013 | §5.4 Protocol handler | Path guard modularization | Decoupled `resolveInside` into `src/main/path-guard.ts` without Electron runtime dependencies. | Enables standalone unit testing under plain Node/Vitest without requiring Electron runtime context. |
| DEV-014 | §5.4 Protocol handler | Range request handling | Implemented `fs.createReadStream` + `Readable.toWeb` with 206 / 416 responses instead of relying on `net.fetch(file://...)`. | Empirical testing demonstrated that `net.fetch` on `file://` URLs in Electron 44 returns HTTP 200 with `Content-Range: null`, breaking partial content streaming. |
| DEV-015 | §5.4 Protocol handler | Asset headers & MIME mapping | Added strict CORS (`Access-Control-Allow-Origin: aeroshell-app://app`), `Vary: Origin`, Expose-Headers, CORP same-origin, and explicit MIME maps (including `.wasm: application/wasm`). | Ensures cross-origin isolation and WebAssembly worker streaming compliance under strict CSP. |
| DEV-016 | §5.4 Protocol handler | Multi-range requests | Multi-range requests (comma-separated byte ranges) are rejected with HTTP 416 Range Not Satisfiable. | Deliberate design choice: RFC 9110 §14.2 permits ignoring or rejecting multi-range requests. CAD viewports stream single contiguous byte ranges for binary geometry buffers; rejecting multi-range eliminates multipart parser overhead and DoS attack surface. |
| DEV-017 | §7.1 Switches, §9.1 CI | Compile-time stripping of test flags | `AEROSHELL_TEST*` environment branches are stripped in production builds via esbuild `define: { 'process.env.AEROSHELL_TEST': 'undefined', ... }`. | Guarantees test hooks (userData overrides, hostile window spawning, software GL) cannot be activated in production binaries. |
| DEV-018 | §5.1 Native module, §9 CI | `/Qspectre` build configuration | Revisit `/Qspectre` in M7 as a conditional CMake option (`ENABLE_SPECTRE`, default ON in CI runners with MSVC Spectre component, OFF for local builds if missing). | Balances strict supply-chain compiler hardening in CI with frictionless local development across machines without optional VS Spectre components. |
| DEV-019 | §5.3 Main process, §5.5 IPC | Modular IPC security guards | Separated `assertTrusted` and `handleCaptureHeapSnapshot` into pure TypeScript module `src/main/ipc-guards.ts`. | Enables 100% isolated unit test coverage under Vitest without requiring Electron runtime processes or native window handles. |
| DEV-020 | §8 Crash & Diagnostics | Heap snapshot policy & rate limiting | Enforced strict gating: snapshots permitted only in dev mode (`!app.isPackaged`) or when Windows Registry DWORD `EnableDiagnostics` is 1; rate limited to 1 call per 60 seconds; retain max 5 snapshots. | Prevents disk exhaustion, DoS attacks, and unauthorized memory dumps in enterprise production environments. |
| DEV-021 | §5.1 Native module, §7 GPU telemetry | Addon metric field mapping | Mapped native `aero_win_bridge.node` memory and GPU fields into strongly typed Zod schemas, converting bytes/KB to MB consistently. | Guarantees uniform numeric representations across Windows native APIs, Electron main process, and sandboxed renderer. |
| DEV-022 | §2 Baseline, §5.5 IPC | Zod version pinning | Pinned `zod: "3.24.2"` | Stable, exact dependency version ensuring strict schema validation (`.strict()`) without unexpected runtime schema deprecations. |
| DEV-023 | §5.4 Protocol handler, §7 Viewport | Draco / KTX2 workers deferred to M6 | Draco mesh compression and KTX2 texture transcoding workers deferred to M6; verified off-thread worker communication via `parse-worker.js`. | Focuses M4 on Three.js WebGL viewport lifecycle, context-loss recovery, rAF metrics, and GPU truth validation before adding complex transcoding pipelines. |
