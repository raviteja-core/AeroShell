# AeroShell

A hardened Electron desktop shell designed for high-performance WebGL/Three.js CAD viewport workloads with a Windows C++20 Node-API addon (`DXGI` GPU + Win32 memory + allowlisted registry reads), a secure custom-protocol asset pipeline, typed IPC layer, memory/crash diagnostics, and statistical leak detection.

---

## Architecture Overview

1. **Host Native Addon (`aero_win_bridge.node`)**:
   - Built with C++20, `/W4 /WX`, `/guard:cf`, `/CETCOMPAT`, and delay-load hook redirecting `NODE.EXE` imports to the host executable.
   - DXGI 1.4 hardware topology query: GPU name, vendor/device IDs, dedicated VRAM, shared system RAM, adapter LUID, and OS-assigned VRAM budget (`IDXGIAdapter3::QueryVideoMemoryInfo`).
   - Win32 system memory metrics (`GlobalMemoryStatusEx`): total physical RAM, available physical RAM, commit limits.
   - PDH Performance Counters (`\GPU Adapter Memory(*)\Dedicated Usage` and `\GPU Process Memory(*)\Dedicated Usage`): AsyncWorker query returning dedicated adapter VRAM usage and per-process VRAM bytes.
   - Allowlisted Windows Registry query: DWORD and String reads restricted strictly to `HKCU\Software\AeroShell`.

2. **Asset & Application Protocols (`aeroshell-app://`, `aeroshell-asset://`)**:
   - Strict Content Security Policy (`script-src 'self' 'wasm-unsafe-eval'`), COOP (`same-origin`), and COEP (`require-corp`).
   - `aeroshell-asset://models/*` streams 3D models with RFC 9110 single-range requests (`bytes=start-end`, `bytes=start-`, `bytes=-suffix`), rejects multi-range with 416, blocks traversal attempts (`%2e%2e`), and strictly validates file extensions.

3. **Memory Pressure Watchdog & Viewport Controller**:
   - Adaptive polling (2.5s visible, 15s hidden) evaluating system RAM, renderer working set, GPU private bytes, and active adapter dedicated VRAM usage.
   - 3-tick hysteresis with lower exit thresholds preventing severity flapping.
   - Dynamic viewport throttling:
     - `NORMAL`: `min(dpr, 2)`
     - `WARN`: `min(dpr, 1)` or `0.75` if `dpr <= 1`
     - `CRITICAL`: `0.75` + ModelCache eviction of unreferenced models
     - Minimization pause via `aeroshell:window-state` IPC event.

4. **ModelCache & Mesh Compression**:
   - LRU model cache with byte budget (256 MB default), in-flight request de-duplication, and recursive disposal hierarchy.
   - Draco mesh compression via Three.js `DRACOLoader` with wasm decoders hosted in `dist/renderer/draco/`.

5. **Diagnostic Pipeline & Security Gates**:
   - `captureHeapSnapshot`: CDP heap snapshot streaming with rate limiting (1/60s) and max 5 files.
   - `captureContentTracing`: Chromium content tracing with rate limiting (1/60s), max 3 files, and 50 MB free disk space check.
   - Navigation guards, allowlisted window opening (`shell.openExternal`), and hostile origin rejection (`assertTrusted`).

## Build & Test Commands

```bash
# Install dependencies
npm install

# Compile Windows native addon
npm run compile:native

# Typecheck TypeScript
npm run typecheck

# Run unit tests (Vitest)
npm test

# Run E2E tests (Playwright)
npm run test:e2e

# Run native smoke verification
npm run native:electron-smoke

# Run Soak Test Harness
npm run soak           # Default 60 cycles
npm run soak:ci        # CI short mode (30 cycles)
npm run soak:ladder    # Statistical ladder with seeded leak detection

# Build production bundle (verified 0 test flags)
npm run bundle
```

## DevTools Heap Snapshot Comparison Workflow

When diagnosing memory leaks in the CAD viewport:

1. **Capture Snapshots**:
   - Baseline Snapshot: Captured at startup or post-warmup cycle.
   - Stress Snapshot: Captured after N cycles or automatically generated by the soak harness upon test failure (`soak-snapshot-cycle-N-final-failure.heapsnapshot`).
   - Programmatically via DevTools or IPC: `await window.aeroPlatform.captureHeapSnapshot()`.

2. **Open in Chrome DevTools**:
   - Open Google Chrome or Chromium.
   - Press `F12` to open DevTools, then navigate to the **Memory** panel.
   - Click the **Load** button at the bottom of the left sidebar.
   - Load Snapshot 1 (baseline) and Snapshot 2 (post-run).

3. **Switch to Comparison View**:
   - In the left sidebar, click Snapshot 2.
   - In the top perspective dropdown (default: "Summary"), select **Comparison**.
   - In the baseline selector next to it, select Snapshot 1.

4. **Analyze Retainers & Leak Root**:
   - Sort columns by **# Delta** or **Size Delta** descending.
   - Inspect key CAD allocations:
     - `Mesh`, `BufferGeometry`, `BufferAttribute`
     - `Uint8Array`, `Float32Array`
     - `WebGLTexture`, `ImageBitmap`
   - Expand the target constructor to view leaked instances (`@id`).
   - Click an instance to open the **Retainers** tree at the bottom.
   - Trace the path to GC Root:
     - Identify holding references (e.g. event listeners on `window`, module-scoped caches, Three.js scene graphs, or un-cleared arrays).

## Offline Minidump Symbolication

AeroShell crash dumps are stored under `%LOCALAPPDATA%\AeroShell\Crashpad\reports\*.dmp` (or test-isolated temporary userData directories).

To symbolicate a minidump using Windows Debugger (`cdb.exe` / `windbg.exe`):

1. **Set Symbol Path**:
   ```cmd
   set _NT_SYMBOL_PATH=srv*C:\Symbols*https://msdl.microsoft.com/download/symbols;srv*C:\Symbols*https://symbols.electronjs.org;C:\dev_store\PROJECT\AeroShell\build\Release
   ```

2. **Open Minidump**:
   ```cmd
   cdb -z "C:\Users\<user>\AppData\Local\AeroShell\Crashpad\reports\<uuid>.dmp"
   ```

3. **Inspect Crash Analysis**:
   ```cmd
   !analyze -v
   kp
   lm vm aero_win_bridge
   ```
